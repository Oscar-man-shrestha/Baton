Earlier findings:
- Good safety rule.
- The entry point becomes `@app.command() def run(dry_run: bool = False)`.
- Append a counter before the extension: `report.pdf`, `report (2).pdf`, `report (3).pdf`.
- Group moves by destination drive, show a progress bar with rich.progress for large batches, and check free space first with shutil.disk_usage so a full drive fails before anything moves.
- On macOS use a launchd agent (a plist in ~/Library/LaunchAgents with StartCalendarInterval), on Linux a systemd user timer, on Windows Task Scheduler.
- A small TOML file at ~/.config/tidy/config.toml works well: a `[folders]` table mapping patterns to names, like `pdf = 'Documents'` and `jpg = 'Pictures'`.
- 3.11 or newer: tomllib is built in, error messages are much clearer, and it's what most current Linux distributions and Homebrew ship.
- Then `pipx install .` from the project folder installs it in its own environment, and `pipx install git+https://github.com/you/tidy` works once it's on GitHub.
- Moves within one drive are just renames and are instant; across drives, shutil.move copies then deletes, which is slow for big files.
- I'd add a `tidy schedule` command later that writes the right file for the platform, but start by documenting the three manual setups in the README so people can choose.
- rich.table.Table with three columns: file, from, to.

- `is_file()` follows symlinks, so a link to a file in another folder would be moved as a link (the target stays put).

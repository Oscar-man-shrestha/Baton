## 1. User

my Flask app gives a 500 error after login. traceback says KeyError: 'user_id' in /dashboard. it works on localhost but not on the deployed site behind nginx with https

## 2. Assistant

A KeyError on `session['user_id']` right after login usually means the session cookie isn't coming back. Common causes:

- The cookie is marked `Secure` but the app thinks it's on http.
- `SESSION_COOKIE_SAMESITE` blocks it.
- The SECRET_KEY differs between workers.

Can you check whether the browser stores the session cookie after login?

## 3. User

the cookie is there. I already tried increasing the gunicorn timeout, that didn't change anything

## 4. Assistant

Then the timeout isn't it. With 4 gunicorn workers, a SECRET_KEY generated at startup (`os.urandom`) differs per worker, so a session signed by one worker is rejected by another. That matches "works on localhost" (one process).

Fix: set a fixed SECRET_KEY from an environment variable:

```python
app.config['SECRET_KEY'] = os.environ['FLASK_SECRET_KEY']
```

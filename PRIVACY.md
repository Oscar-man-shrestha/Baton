# Handoff privacy policy draft

**Date:** 2026-10-21. This draft must be published at a stable public URL before a Chrome Web Store submission.

Handoff reads rendered conversation text and the unsent prompt in the editor only on the supported AI chat sites named in its manifest. It stores up to 300,000 characters of rendered chat text per chat as a local transcript and uses that text to maintain a local project brief, suggest a destination, show a reviewable handoff draft, and compare current chat size with past chats that showed visible limit notices. The comparison is low confidence and does not know the provider's remaining allowance. The unsent prompt is used for the current suggestion and an approximate token count while typing; it is not saved separately. The prompt status line appears below the composer only when there is room, and can be absent on some layouts. Transcripts, briefs, settings, diagnostics, and limit-event timestamps with approximate token counts are stored in Chrome's local extension storage on the user's device. Users can export projects, choose automatic expiry of saved briefs and projects after 7, 30, or 90 days, or delete all Handoff data from the options page. Expiry runs when Handoff opens.

Handoff can open Gemini so the user can select a Google account through Google’s own profile menu. It does not select accounts itself. Handoff does not operate an account, analytics, or synchronization server. It does not read cookies, passwords, or provider session credentials. It does not submit messages. The user chooses a destination and presses Send there. The extension can optionally open a destination tab and insert text into its editor as a draft.

The local transcript can be incomplete if messages were never rendered, windows do not overlap, or its size cap trims early text. The compact brief can omit details. If the user selects “Try to include older messages” before capture, Handoff temporarily scrolls the current chat to read additional rendered messages, then restores the prior scroll position. This is a local, user-initiated action and may still miss some messages on sites that virtualize or load history differently.

Handoff may recognize common key and personal-data patterns before rendering a draft, but automated detection can miss sensitive data. Users should inspect and edit the draft. Copying a draft or sending it in a provider's chat is governed by that provider's own policies.

The source includes an opt-in, hash-verified remote selector updater, but the current interface does not enable it. If introduced later, the privacy policy and permission disclosures must be updated with the exact endpoint and data transferred.

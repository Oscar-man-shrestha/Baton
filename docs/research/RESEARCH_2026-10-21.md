# Capture, limits, and interface research addendum

Checked 2026-10-21. This supplements `RESEARCH.md`; store figures and undocumented response shapes may change. Public source inspection verifies implementation patterns, not that a competitor works on today's signed-in sites. No claim to have inspected every extension or the whole internet.

## Capsule Infinity

[Repository](https://github.com/ahmadiscoding/capsule-infinity-chrome-extension), inspected commit `8588064`. Read generic capture, accumulator, local storage, and Supabase client code. Generic capture clones service message containers, removes extension UI, and exports text. A scroll accumulator collects changing windows and restores position. Some provider paths use internal APIs. Google OAuth/PKCE and Supabase provide account storage.

Lessons applied independently: observe rendered messages, accumulate overlapping windows, retain local context, distinguish capture from compact handoff, show recent contexts and folders, offer a sidebar and optional cloud backup. Avoid whole-page text that captures unrelated sidebar chat titles. Avoid global text deduplication, which can erase intentional repeated prompts. Avoid truncating the user's original goal or the final assistant question just to produce a short export. Do not copy a competitor's backend credentials, logos, brand, or claims.

The user's Gemini comparison is useful evidence: Handoff's supplied full capture contains the JSON data structure, feature checklist, and final platform question; the supplied Capsule export cuts off in the color-palette section and includes interface labels. This single sample does not establish universal superiority. The duplicate “You said” wrapper in Handoff was a real defect; the message-body selector now prefers the actual user text, with regression fixtures. Live Gemini validation remains necessary.

## Claude Monitor: why it can show 31% and 5%

[Website](https://claude-monitor.com/) and [public source](https://github.com/claude-monitor/claude-monitor-browser-extension), inspected commit `d0d9f4c31d5d2172605b27de67711c85a96b30fa`. Read `extension/background.js`, `extension/page/stream.js`, and security notes.

- Authenticated private usage requests read organization/session/weekly/model buckets. The browser attaches the existing session; the extension does not need to read cookie values.
- Free-plan fallback inspects `message_limit` SSE metadata. Newer StreamTimeline responses use a binary parser. The implementation avoids decoding reply text and skips compressed message frames.
- API utilization values use percentage units; completion windows use 0–1 fractions. Null is unknown, not zero. “Exceeded” status can override utilization. These details matter more than drawing a progress bar.
- Toolbar utilization, separate windows, reset countdowns, stale states, and deduplicated 80/95 alerts are useful UI patterns. Account/organization identity and stale cache handling also matter.

Handoff includes an isolated, tested numeric-shape parser for these Claude examples, but **no private API requests, response interception, or binary-stream decoder are enabled or shipped as an active connection**. A parser test does not equal live quota tracking. Visible service-page readings are the active source. The user conditioned permission on legal/account safety; no blanket safety guarantee can be made.

[Anthropic consumer terms](https://www.anthropic.com/legal/consumer-terms), effective 2025-10-08, checked 2026-10-21, restrict automated access except through the API or explicit permission and restrict harvesting. This is a terms-of-service issue, not a determination that an extension is criminally illegal. Store availability or another extension's operation does not establish provider permission. Keep the original brief's restriction until there is an approved integration basis.

## Limits across services

A single universal “free tier percentage” is not a reliable data model. Separate session, weekly, model, and feature quotas; keep prompt-token estimates separate. Do not copy numbers drawn by a third-party extension or written inside an assistant reply as provider truth.

- [ChatGPT Free Tier FAQ](https://help.openai.com/en/articles/9275245-using-chatgpt-s-free-tier-faq): plan/model/tool limits differ; this is not an account-specific remaining balance API. Do not repeat the user's quoted “unlimited everyday text” claim as a universal verified fact.
- [Gemini limits](https://support.google.com/gemini/answer/16275805): model and feature capacity depends on plan and service conditions. Documentation maxima are not the signed-in user's measured remainder.
- [Claude usage versus length limits](https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work): account usage and conversation length are different. Tokenizing one visible conversation does not measure a shared account allowance.
- DeepSeek, Grok, and Perplexity have adapter/notice fixtures in Handoff; account-specific continuous numeric quota tracking has not been verified. No invented five-hour/weekly windows or fixed free-token totals are assigned.

The current active display uses visible semantic service notices/progress bars, rejects chat/sidebar/known extension widgets, separates recognized windows/features, shows reset countdown and observation time, expires stale/reset readings, and provides an unknown state on all six supported domains. Numeric accuracy depends on the service exposing a correct, interpretable figure. Arbitrary third-party DOM injection cannot be authenticated as first-party truth; the widget exclusion rules are a best-effort boundary.

## AIHero handoff lessons

[AIHero handoff article](https://www.aihero.dev/skills-handoff), updated 2026-08-24, checked 2026-10-21. Carry active work, rationale, uncertainty, and an explicit next task. Redact secrets. Reference durable specs/commits only when the destination can access them. A local file path alone is insufficient when moving to another web service. Preserve exact latest code or provide full export instead of replacing it with an inaccessible reference. Do not turn an assistant's proposed stack into a verified user decision.

Applied: explicit next-task editing, provenance-aware brief schema, source URL/date/coverage in full exports, local durable saves, verbatim code artifacts, compact/full modes, and redaction before handoff. No skill from the article was installed or executed.

## 0.2.1 follow-up audit of the nine requested outcomes

Re-opened the Claude Monitor and AIHero primary pages on 2026-10-21. Claude Monitor's README confirms stale state/account-change handling and separate per-model buckets; these are useful correctness requirements, not evidence that another provider exposes equivalent quotas. No new review evidence established the cause of the low scores in the attachment.

The follow-up audit found and fixed concrete local implementation errors: unchanged relative countdowns could drift forward; simultaneous notification handlers could overwrite each other's delivered-alert records; a smaller subsequent bucket could replace a more constrained toolbar bucket; open chat tabs did not immediately read other tabs' saved window updates; and malformed/negative/decimal percentages and unrelated network retry notices needed stricter interpretation. Regression tests exercise the actual background message handler as well as the pure parsers. Service-page context for progress bars is now bounded to one quota indicator, so a weekly reading does not borrow a session reset from a broad parent container.

The active data-source boundary is unchanged. No private provider API request or response interception has been enabled. This is an improvement to observation correctness and display consistency, not a claim of exact universal quota access.
